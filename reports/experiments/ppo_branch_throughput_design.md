# 冻结 PPO 反事实续控加速：测量协议

2026-10-22。此前 24-seed Top-2 同状态研究的 48 条分支耗时约 34 分钟。对一条 1000 块分支的 cProfile 显示，正式合法落点生成累计约 5.15/7.83 秒，候选特征约 1.71 秒，模型推理约 0.76 秒。已有 `LongCandidateTetrisEnv` 的评测专用 bitboard 落点与候选特征实现经过 Core/JS Parity；本轮只将其用于**未来新反事实实验的可选执行器**，不修改正式 Core、冻结模型或旧实验数据。

实现 `training/evaluation/fast_counterfactual.py`，输入与旧 `ppo_fresh_counterfactual.branch` 相同，保持单步替换、冻结 PPO 确定性续控、合法动作 Mask、正式计分与右截断语义。旧函数继续保留。

验证与测量事前固定：

- 单元测试从相同 seed 建两个环境，200 步逐步比较公开 Core 状态、动作、合法 Mask、237 维状态和全部候选特征；另比较 300 块分支的完整累计分数、四消及截断输出。
- 使用已完成的诊断数据 `1540000`（死亡附近）、`1540004`（存活对照）、`1541002`（独立探索死亡局）中已保存的 Top-2 首动作；这些历史 seed 只用于**性能与语义复核**，不重新评估模型质量。
- 每状态续控 1500 块，旧/新执行器都先预热 100 块，再各测 3 次，交替执行顺序；每次要求完整结果对象逐项一致。计时从开始续控到返回，不包括模型和快照文件加载。固定 CPU 单线程；报告每种实现的总墙钟、配对速度比、中位数、峰值进程 RSS，以及实际是否死亡/右截断。
- 预算最多 3×2×3×1500=27,000 条续控步，墙钟最多 5 分钟；所有结果写入独立 `runs/ppo_branch_throughput_benchmark/`，保留原始样本文件哈希、模型 SHA256、代码 SHA256、配置与测量时间。
- 只有全部逐步 Parity、3 组完整输出一致且实测有明确吞吐提升，才保留优化；若不一致，停止并记录，不改正式规则或网页。

性能结果只适用于本机 RTX 3050 游戏本的 CPU 评测链路和这些样本，不把微基准外推为训练加速或模型质量改善。
