# PPO 30M 多候选反事实研究设计

协议 `pilot_v1_50_states_top5_safe_well_256_then_1000` 在任何新反事实结果生成前冻结于 `runs/ppo30m_multiaction_counterfactual/protocol.json` 和 `selection.json`。PPO 与 BC 模型按原 SHA256、Policy、Observation、Feature、Action Space 校验；原权重、Core 和历史结果不变。

从旧 V2 训练组 730000..730015 的已验证轨迹和 Core 快照选 46 个状态，按距 PPO 轨迹死亡 0–250、251–500、501–1000 块及正常对照分层。每 seed 最多 5 个，状态间至少隔 50 步。死亡距离只用于离线选样，不作为候选输入。730100..730103 和旧正式测试组不参与本试点。

候选只来自正式合法 Action Mask：PPO Top1、BC、PPO Top5、一步公开风险最低的动作，以及尽量保留深井的动作。动作去重并保存全部来源、PPO 概率/排名、Hold、一步风险、深井、公开下一块合法落点与后续可见方块状态。每状态最多 8 个动作。风险筛选和下一块模拟仅使用棋盘、Hold、Next 3。

所有分支从相同 Core/RNG 快照出发，第一步执行候选，此后统一由冻结 PPO 确定性续控。PPO 基线必跑到 1000 块或死亡，并和原 V2 分支的存活/死亡结果核对。其他候选先跑 256 块；如果仍活且在共同 256 块得分达到 PPO 的 75%，按冻结规则延至 1000 块。分支结果逐个原子保存；已有结果需匹配协议、模型、选样、候选和状态哈希才可复用。短窗淘汰仅是预算筛选，不能证明长期无益。

A 类要求 PPO 原动作有明显风险、PPO 在 1000 块内死亡、候选多活至少 250 块、共同存活至少 100 块、共同得分至少 90%、共同四消不低于 90%（PPO 少于 2 次时不允许减少）、公开后续 Current/Hold/Next 与 PPO 一致、一步风险不高于 PPO，深井最多损失 1 格。未达到 A 但延长生存者归 B；其余归 C。多个 A 可共存。观察上限按右截断；不比较不同存活长度的总分作为高分能力证据。此严格标准只是试点标签，不是在线策略收益证明。

同 46 个起点和同一 A 标准比较仅 PPO/BC 与多候选，报告每状态、每替代分支及每 CPU 小时的 A 产出。只有非 BC 的 A 至少 3 个、覆盖至少 2 个 seed、且每 CPU 小时 A 状态产出不低于 BC 对照的 80%，才认为值得另立协议评估第二批；第二批不会自动启动。本轮不训练新模型。
