# Candidate imitation learning: V2 Hold → BC → PPO

Status: implementation and small smoke test complete; full experiment is queued behind the existing pure PPO 30M run. Results below are **preliminary** and are not a survival comparison.

## Protocol

- Teacher: `training.traditional.v2.V2(V2Config(mode="hold"))`, version `v2-1`; configuration SHA256 `744b2336f746642c99e8998b67047408f1b88914c1c61737531bbc9cc356d8cf`.
- Samples come from real `TetrisCore` episodes. Only `get_public_observation()` and canonical legal placements reach the teacher. The hidden 7-Bag and RNG state are never passed to the teacher or saved as model inputs.
- Each episode is a compressed, atomic shard with SHA256 verification. BC train and validation splits use different whole episode seeds. Formal final-test seeds are excluded from model selection.
- Candidate features and action masks are generated by the existing `candidate_features`; V2 chooses the original `actionId`. The actor-only loss is negative masked log probability of the teacher action. The Critic is checked unchanged.
- BC starts from a copy of the pure PPO 20M checkpoint. BC updates add **zero PPO environment steps**. PPO fine-tuning will start a new transaction run with fresh optimizer and random streams, using the BC actor and unchanged 20M Critic.

## First smoke result

Two 128-step teacher trajectories yielded 256 unique public states and 101 Hold labels (39.5%). No state reached board height 12, confirming that teacher-only trajectories underrepresent danger states; `label_public()` is the reserved DAgger label interface.

The compressed shards used 152,663 bytes, about 596 bytes per sample. At that density, 200,000 samples would use about 119 MB before manifest and filesystem overhead. Actual full-run size and collection speed will be recorded after collection.

A separate 1,000-step single-seed timing run completed in 10.04 seconds, about 100 samples per second on one CPU process, with a 41 MB peak resident set and a 600 KB compressed shard. Linear extrapolation gives roughly 34 minutes of collector wall time for 200,000 samples; full-run speed may change with board state and concurrent load. Its 1,000 public states were unique, 35.5% of labels used Hold, and none reached height 12.

Using one seed for training and another for BC validation (128 samples each), three actor-only epochs produced:

| Metric | Before BC | Epoch 3 |
|---|---:|---:|
| Train loss | 3.941 | 3.489 |
| Validation loss | 4.329 | 3.894 |
| Validation Top-1 | 35.9% | 38.3% |
| Validation teacher-action probability | 31.4% | 34.5% |

Save/load produced matching policy outputs. A 500-piece game completed with legal actions, reaching the cap. Both pure PPO 20M and the smoke BC model reached that cap; this small test cannot establish a survival improvement.

## Pending matched comparisons

The queued full experiment will collect at least 200,000 expert samples, run BC, then compare pure PPO 20M, pure PPO 30M, 20M PPO + BC, 20M PPO + BC + 2M PPO, and V2 Hold on the **same 32 validation seeds and 20,000-piece cap**. It will report mean and median survival, P10, cap count, and lines cleared. The decision to extend fine-tuning to 10M depends on matched survival results, especially P10. No 50M or 100M expansion is scheduled.
