# PPO学习率受控开发实验

本实验是持续开发中的归因与选参阶段，不是独立确认，也没有自动发布模型。

## 前一轮结果

`autonomous_ppo_20261105`的524288步检查点，在相同8个验证种子、5000块上限、相同评测器下，平均正式得分比冻结PPO30M低8.41%，8/8得分下降。双方全部触顶，因此无法据此判断谁长期存活更久。该轮已在569344步结束，完整事务、优化器/RNG/worker快照、评测模型及来源提交保存于其`review/`目录。

复核发现该轮继承了性能短测的gamma0.999/GAE0.98及100000块训练上限；冻结PPO30M原有值为0.995/0.95及10000。奖励、网络不变，但这些额外差异让“延长训练”的效果存在混杂；不能只凭一次实验认定哪个参数导致退化。

## 本轮固定与变量

| 项目 | 配置 |
|---|---|
| 初始模型 | 冻结PPO30M，SHA256 eb859b8989efe8f3332393ed57110036979b03bb4d3d8d8316d080cf04b2da34 |
| 硬件 | CUDA＋8环境、六个物理核心、CPU250%、6GiB，原温控 |
| 学习设置 | gamma0.995、GAE0.95、训练单局10000、原奖励与网络 |
| 唯一分组变量 | 学习率3e-4与3e-5 |
| 训练种子 | 两组同为1590000–1590007 |
| 初始化 | 都只迁移冻结策略权重，优化器重新初始化；不声称原30M事务原位续训 |
| 初筛预算 | 每组262144步（64个完整4096步事务） |
| 后续上限 | 预设2097152步，筛选完成后不自动扩展 |
| 开发评测 | 同8个验证种子、最多5000块，与新补齐的冻结模型基线配对 |
| 操作总预算 | 6小时，单阶段另有运行时间限制 |

探索性扩展候选条件：8局全部到达5000块，平均已观测正式得分至少为基线99%；若通过者相差不超过0.005个得分比，优先较低学习率。该条件只是下一步复核的筛选标准，不是棋力改善、独立确认或上线验收。

训练器新增有限正数学习率覆写验证。8项来源身份/参数验证测试通过，真实CUDA8的两个4096步事务记录学习率均为3e-5，且事务校验通过。旧运行的来源哈希不被静默改写；恢复旧实验必须使用其记录的源码版本。

## 执行与接手

目录：`runs/autonomous_lr_control_20261105/`。原tmux任务因目标暂停已结束；15:11恢复后由轻薄本用户服务`tetris-lr-control-20261105.service`托管，继续参考组已有139264步和低学习率组已有8192步。队列顺序为参考学习率训练/开发评测，再补齐低学习率训练并评测。检查`status.json`、服务MainPID及实际训练PID后再操作，不重复启动。

`scripts/run_learning_rate_control.py`冻结训练源码、基线文件身份，缓存评测核对模型SHA及实际步数。用户目标暂停、显式预算限制或目录中的`STOP`文件会终止当前受保护子任务；AI账户额度暂时不足不强行中断已授权且有界的本地计算。

模型、结果、完整诊断及队列阶段均留档；正式PPO30M与BC不替换。后续根据实测结果继续开发，必要时补充更长局开发基线；禁止将5000块与10000块结果直接排序成全局冠军。
